# Writing Agent References

Use this branch for agent-facing knowledge that is loaded only when a named condition applies.

## Require a real branch

Create an Agent Reference only when the material is too conditional or substantial for the owning Steering File or Skill. Ordinary human documentation is not an Agent Reference merely because an agent could read it.

Identify the owning source and add an incoming Context Pointer before writing the reference. One reference should answer one recognizable branch of decisions. If no stable pointer location exists, do not create an orphan file.

## Make the reference actionable

Start with the condition under which the file is relevant. Organize around decisions and procedures, not a narrative introduction. Record domain facts only when they change agent action. Name authoritative files, commands, or interfaces precisely, and separate requirements from examples.

Keep one Single Source of Truth. When this reference explains material owned elsewhere, point to that source and state when to inspect it; do not mirror content that will drift.

End with Completion Criteria or a clear handoff back to the owning workflow. Verify every path and command from the consumer's scope.
